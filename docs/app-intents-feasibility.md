# App Intents feasibility

Feasibility of a personally installed iOS app that exposes Swift App Intents, replacing hand-built Shortcuts.
Researched 2026-09-21 against Xcode 27.0 and iOS 27 docs. Claims cite Apple, WebKit or project-owner sources; forum posts are labelled _secondary_. **Unverified** marks claims with no primary source found.

## TL;DR

- **Feasible.** Any `AppIntent` in an installed app appears as an action in Shortcuts with no App Shortcut phrases, and from there runs from Siri, Control Center, the Action button, Back Tap, widgets, Apple Watch and automations. A dev-signed app installed from Xcode works ([WWDC22 10032](https://developer.apple.com/videos/play/wwdc2022/10032/), [verification guide](https://developer.apple.com/documentation/appintents/verifying-your-app-intents-implementation)).
- **Hard limits.** Intent metadata is extracted at build time, so new intent types, parameters and enum cases need an Xcode rebuild. Background runs get 30 s unless the intent adopts `LongRunningIntent` (iOS 27).
- **Recommended architecture.** Native Swift App Intents only, option (b): each new behaviour is a Swift intent, rebuilt with Xcode and installed to the phone (Claude writes and installs them; about a minute per intent). This gives full native API reach and native Shortcuts UX. Script runtimes and DSLs ((a), (d)) reach only hand-written bridges, so they are not used. Dynamic entities (c) cover runtime-variable lists.
- **On-device results.** Custom actions, entity pickers, Action Button runs from a locked device and Personal Team installs without an App Group all work on an iPhone 17 (iOS 26); section 8.
- **Distribution.** Paid Developer Program ($99/yr) plus Xcode install is the least friction. The free tier works but expires every 7 days and allows 10 App IDs per 7 days.
- **Policy.** Native intents raise no policy issue. App Review guideline 2.5.2 governs App Store apps only; DPLA 3.3.1(B) governs downloaded interpreted code (options (a), (d)).

Core types:

- **`AppIntent`**: `title`, `parameterSummary`, `perform()`, `supportedModes`, `authenticationPolicy`, `isDiscoverable` (default `true`), `allowedExecutionTargets`. Code can live in the app, an App Intents extension, a framework or a Swift package ([AppIntent](https://developer.apple.com/documentation/appintents/appintent), [isDiscoverable](https://developer.apple.com/documentation/appintents/appintent/isdiscoverable)).
- **Parameter types**: `Bool`, `Int`, `Double`, `String`, `AttributedString`, `Duration`, `Date`, `Decimal`, `Measurement`, `URL`, `Array`, `Set`, `EntityCollection`, `IntentPerson`, `IntentFile`, `IntentCurrencyAmount`, `IntentPaymentMethod`, `SystemShortcut`, `@UnionValue`, `DateComponents`, `PersonNameComponents`, `PHAsset`, `PlaceDescriptor`, `RecurrenceRule`, plus your `AppEntity` and `AppEnum`. Results support the same set ([Adding parameters](https://developer.apple.com/documentation/appintents/adding-parameters-to-an-app-intent)). The table lists no dictionary type, so structured output goes out as a JSON `String`.
- **Optional parameters**: a non-optional property is required. Throw `$param.needsValueError(...)` to ask for a value mid-`perform()` ([Adding parameters](https://developer.apple.com/documentation/appintents/adding-parameters-to-an-app-intent)).
- **`AppEnum`**: a "predefined, static set of values". Case titles must be a dictionary literal because the compiler reads them at build time ([AppEnum](https://developer.apple.com/documentation/appintents/appenum), [WWDC22 10032](https://developer.apple.com/videos/play/wwdc2022/10032/)). Apple says not to conform one type to both `AppEntity` and `AppEnum`.
- **`AppEntity` and queries** ([Entity queries](https://developer.apple.com/documentation/appintents/entity-queries)):
  - `EntityQuery`: `entities(for:)` by ID, plus optional `suggestedEntities()` ([EntityQuery](https://developer.apple.com/documentation/appintents/entityquery)).
  - `EntityStringQuery`: free-text lookup.
  - `EntityPropertyQuery`: property and comparator search, sortable; powers Shortcuts' Find actions ([WWDC26 310](https://developer.apple.com/videos/play/wwdc2026/310/)).
  - `EnumerableEntityQuery`: short lists.
  - `DynamicOptionsProvider`: runtime option lists for any parameter type ([DynamicOptionsProvider](https://developer.apple.com/documentation/appintents/dynamicoptionsprovider)).
  - `UniqueAppEntity`: singleton entities.
  - `IndexedEntity`: Spotlight indexing.
  - `EntityCollection` (iOS 27): identifiers only, resolved lazily ([EntityCollection](https://developer.apple.com/documentation/appintents/entitycollection)).
- **Parameter summary**: `ParameterSummaryBuilder` with `When` and `Switch` conditions. It is static metadata ([App intents collection](https://developer.apple.com/documentation/appintents/app-intents)).
- **`perform()` results**:
  - `.result()`.
  - `ReturnsValue<T>`.
  - `ProvidesDialog`.
  - `ShowsSnippetView` (static SwiftUI view).
  - `ShowsSnippetIntent` (interactive; the `SnippetIntent` type is iOS 26) ([Snippets](https://developer.apple.com/documentation/appintents/displaying-static-and-interactive-snippets)).
  - `OpensIntent` returns another intent ([App intents collection](https://developer.apple.com/documentation/appintents/app-intents)).
  - Siri AI may not show `IntentDialog` or `ShowsSnippetView` ([Snippets](https://developer.apple.com/documentation/appintents/displaying-static-and-interactive-snippets)).
- **Errors**: throw `AppIntentError`, or your own `CustomLocalizedStringResourceConvertible` errors. Sub-kinds: `PermissionRequired`, `UserActionRequired`, `Unrecoverable` ([AppIntentError](https://developer.apple.com/documentation/appintents/appintenterror)).
- **Confirmation and choice**: `requestConfirmation` (with `conditions:` since iOS 18), `requestChoice(between:)` (iOS 26), `requestValue` ([AppIntent](https://developer.apple.com/documentation/appintents/appintent)).
- **Authentication**: `IntentAuthenticationPolicy` is `alwaysAllowed` (default, "including when the device is locked"), `requiresAuthentication` or `requiresLocalDeviceAuthentication` ([authenticationPolicy](https://developer.apple.com/documentation/appintents/appintent/authenticationpolicy), [IntentAuthenticationPolicy](https://developer.apple.com/documentation/appintents/intentauthenticationpolicy)).
- **Chaining in Shortcuts**: an action's output feeds the next action's parameters; `InputConnectionBehavior` controls how a parameter connects to the previous output ([App intents collection](https://developer.apple.com/documentation/appintents/app-intents)). Custom types cross apps through `Transferable` and `IntentValueRepresentation` ([WWDC26 345](https://developer.apple.com/videos/play/wwdc2026/345/)).
- **Files**: `IntentFile` takes on-disk input and output; `FileEntity` (iOS 18) models a file as an entity ([Updates](https://developer.apple.com/documentation/updates/appintents)).
- **Foreground and background**: `supportedModes` is `.background`, `.foreground(.immediate|.dynamic|.deferred)`, or a combination. It is only a suggestion. `systemContext.currentMode` reports the actual mode, and `continueInForeground()` errors from an extension ([supportedModes](https://developer.apple.com/documentation/appintents/appintent/supportedmodes), [Runtime](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)). By default an intent does not foreground the app ([WWDC25 244](https://developer.apple.com/videos/play/wwdc2025/244/)).
- **Assistant schemas and Siri AI**: `@AppIntent(schema:)`, `@AppEntity(schema:)` and `@AppEnum(schema:)` bind types to system domains (Audio, Calendar, Camera, Clock, Mail, Maps, Messages, Notes, Phone, Photos, Reminders, search, plus Shortcuts-only Books, Browser, Files, Journaling and others). Mail, Clock and Messages require adopting every schema in the group ([Schema domains](https://developer.apple.com/documentation/appintents/app-schema-domains), [Discoverable by Apple Intelligence](https://developer.apple.com/documentation/appintents/making-actions-and-content-discoverable-by-apple-intelligence)). Whether Siri AI invokes non-schema custom intents is **unverified**; they are usable from Shortcuts.
- **Visual Intelligence**: `IntentValueQuery` (iOS 26) returns app entities for camera and screen matches ([Visual intelligence](https://developer.apple.com/documentation/appintents/visual-intelligence)). Not relevant to a personal automation app.

## 4. Runtime limits and process model

- **Time.** Background intents get 30 s; `LongRunningIntent` (iOS 27) extends this if `progress` is updated regularly, with a Live Activity showing progress. macOS has no limit ([LongRunningIntent](https://developer.apple.com/documentation/appintents/longrunningintent)). The system cancels an intent that exceeds 30 s without reporting progress ([CancellableIntent](https://developer.apple.com/documentation/appintents/cancellableintent)). `LongRunningIntent` also supports background GPU with an entitlement ([WWDC26 345](https://developer.apple.com/videos/play/wwdc2026/345/)). Without it, the 30 s limit applies to every OS that supports `CancellableIntent` (iOS 26.4+).
- **Where code runs.**
  - Code in the app bundle runs in the app process. Background runs launch the app "in a special mode without scenes".
  - Code in an App Intents extension always runs in the background.
  - Widget-extension control intents run in the extension.
  - The system prefers the extension for background intents unless the app is already running, and always uses the app if it is in the foreground.
  - `allowedExecutionTargets` (iOS 27) overrides this.
  - ([Runtime](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents), [IntentExecutionTargets](https://developer.apple.com/documentation/appintents/intentexecutiontargets)).
- **Memory.**
  - Apple says only that the app process has "higher memory limits" than an extension ([WWDC22 10032](https://developer.apple.com/videos/play/wwdc2022/10032/)).
  - No numeric limit for App Intents processes was found in Apple docs: **unverified**.
  - An Apple engineer states a 30 MB limit for SiriKit Intents extensions and suggests in-app handling for more (_secondary_, SiriKit not App Intents, [thread](https://developer.apple.com/forums/thread/655189)).
  - "Increased Debugging Memory Limit" is debug-only and needs a paid team ([Capabilities](https://developer.apple.com/help/account/reference/supported-capabilities-ios)).
- **Extension boundaries.** Shared code needs an `AppIntentsPackage` because framework metadata is emitted in the framework bundle ([Runtime](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)). Keep intents in the app target unless a Widget extension needs them.
- **Cancellation.** `CancellableIntent` (iOS 26.4) reports whether the user cancelled or the system timed out ([CancellableIntent](https://developer.apple.com/documentation/appintents/cancellableintent)).

## 6. Adding intents without rebuilding

**Build-time extraction.**

- App Intents "statically extract" intents, entities, queries and parameters at build time; Xcode writes a metadata file into the app or extension bundle ([WWDC22 10032](https://developer.apple.com/videos/play/wwdc2022/10032/), [Runtime](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)).
- `appintentsmetadataprocessor` takes a source file list and Swift compiler const-value files and emits the output bundle (local `--help`, Xcode 27.0).
- The output is `Metadata.appintents/extract.actionsdata`, plain JSON. Shipped examples: `/System/Applications/Calculator.app/Contents/Resources/Metadata.appintents`.
- The framework docs list no API to register an intent type at runtime. Runtime-variable parts:
  - Entity lists (`EntityQuery`).
  - Parameter options (`DynamicOptionsProvider`).
  - App Shortcut parameter values ([`updateAppShortcutParameters()`](https://developer.apple.com/documentation/appintents/appshortcutsprovider), `parameterPresentation`).
- Static parts: intent identity, parameter list, parameter summary, `AppEnum` cases, App Shortcut phrases.

**Architecture options.**

| Option                                           | New behaviour without rebuild | Native API reach                                                  | Shortcuts UX                                  | Policy (personal build)                                         | Effort                             | Decision                                                                                              |
| ------------------------------------------------ | ----------------------------- | ----------------------------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------------- |
| (a) Generic `Run Script` intent + JavaScriptCore | Yes: edit script text         | Only host functions you expose; new host functions need a rebuild | One action; `script` and `input` parameters   | DPLA 3.3.1(B) conditions apply; 2.5.2 applies to App Store only | Medium                             | Not chosen: reach limited to bridges; rebuild avoided only for logic, not for new native capabilities |
| (b) Fixed Swift intent library                   | No                            | Full                                                              | One action per intent, native summaries       | Clean                                                           | Low per intent; rebuild per change | **Chosen**                                                                                            |
| (c) Dynamic entities and options                 | Only new entity values        | Same as the intents that consume them                             | Native pickers                                | Clean                                                           | Low                                | Used for runtime-variable lists                                                                       |
| (d) Text/JSON DSL parsed at runtime              | Yes: edit graph               | Only ops you implement                                            | One action; no editor                         | Interpreted-code rules apply                                    | High (rebuilds Shortcuts)          | Not chosen: reach limited to implemented ops; rebuild avoided only for logic; high effort             |
| (e) URL scheme / x-callback bridge               | Yes (in Shortcuts)            | Whatever the target app exposes                                   | Foreground app switch; result via `x-success` | Clean                                                           | Low                                | Fallback only                                                                                         |
| (f) Shortcuts built-ins                          | Yes                           | Shortcuts actions only                                            | Native                                        | Clean                                                           | None                               | Used alongside intents                                                                                |

- **(a) JavaScriptCore.**
  - `JSContext` exists since iOS 7 ([JSContext](https://developer.apple.com/documentation/javascriptcore/jscontext)).
  - On iOS, JSC enables JIT only for processes with the `dynamic-codesigning` or `com.apple.developer.cs.allow-jit` entitlement ([WebKit source](https://github.com/WebKit/WebKit/blob/main/Source/JavaScriptCore/jit/ExecutableAllocator.cpp)). Neither appears in the developer capability list ([Capabilities](https://developer.apple.com/help/account/reference/supported-capabilities-ios)), so expect interpreter-only speed (inference).
  - Guideline 2.5.2 forbids downloading or executing code that "introduces or changes features or functionality" in App Store apps, with an exception for educational code-teaching apps whose source is fully viewable and editable. Guideline 4.7 separately allows HTML5 and JavaScript mini apps and plug-ins ([Guidelines](https://developer.apple.com/app-store/review/guidelines/)).
  - DPLA 3.3.1(B) permits downloaded interpreted code that (a) does not change the app's advertised primary purpose, (b) does not bypass signing, sandbox or security features, and (c) for App Store apps, creates no storefront ([DPLA](https://developer.apple.com/support/terms/apple-developer-program-license-agreement/)). It covers TestFlight and Ad Hoc builds. Advertise the app as a scripting tool, and do not present scripts as bypassing OS controls.
- **(c) Dynamic entities.** An `EntityQuery` backed by files or a store gives a picker whose values change without a rebuild (observed on-device, section 8).
- **(e) URL bridge.** `shortcuts://run-shortcut?name=&input=` runs a shortcut from another app ([Guide](https://support.apple.com/guide/shortcuts/run-a-shortcut-from-a-url-apd624386f42/ios)). `shortcuts://x-callback-url/run-shortcut` adds `x-success`, `x-cancel` and `x-error` callbacks, with the shortcut's text output appended as `result` ([Guide](https://support.apple.com/guide/shortcuts/use-x-callback-url-apdcd7f20a6f/ios)). Useful as an escape hatch, not as the core.
- **(f) Shortcuts built-ins for comparison.**
  - "Run JavaScript on Webpage" runs only in Safari or `SFSafariViewController` and needs Allow Running Scripts ([Guide](https://support.apple.com/guide/shortcuts/apdb71a01d93/ios)).
  - "Run script over SSH" exists (named in [iOS 13.1 security notes](https://support.apple.com/en-us/103821)) and needs a remote host. Its presence in iOS 27 is **unverified**.
  - iOS 27 adds Storage (persisted values across runs), the Use Model action and new automation triggers ([WWDC26 310](https://developer.apple.com/videos/play/wwdc2026/310/)).
  - "Run Shell Script" for Shortcuts on Mac: **unverified**.

**Recommendation.**

1. Native Swift App Intents only (b): one intent per behaviour, each with a proper parameter summary and typed output. Claude writes, builds and installs each; about a minute per intent.
2. Use dynamic entities and options (c) for lists that change at runtime.
3. Keep intents in the main app target. No App Intents extension until measurements justify one. Add a Widget extension only for custom Controls.
4. Return JSON strings for structured results and let Shortcuts parse them.
5. Do not build (a) or (d): their reach stops at hand-written bridges. Use (e) only as a fallback.

Trade-off: every new behaviour needs a rebuild and install. The gain is full native API reach and native Shortcuts actions.

## 7. Prior art

- **a-Shell** (BSD-3, [README](https://github.com/holzschu/a-shell)): generic Shortcuts actions `Execute Command`, `Put File`, `Get File`, runnable "In Extension" or "In App"; ships Python, Lua, JS, C, C++ and TeX. Direct precedent for a generic scripting intent, including the extension-versus-app split.
- **Scriptable** ([scriptable.app](https://scriptable.app/)): "Run scripts from Siri Shortcuts", ES6 JavaScript stored as plain files. App Store app.
- **WidgetsWall** (28 stars, [repo](https://github.com/MisterZhouZhou/WidgetsWall)): a `RunJavaScriptShortcut` `AppIntent` with a `String?` code parameter and `JSContext.evaluateScript`, returning `ReturnsValue<String>`. Confirms the shape compiles; not evidence of runtime behaviour.

## 8. On-device results

Observed on an iPhone 17 running iOS 26, not from Apple docs:

- Custom actions appear in Shortcuts, and their parameter pickers work.
- Dynamic `EntityQuery` values refresh without a rebuild.
- The Action Button runs an intent from a locked device.
- Siri phrases with an entity parameter work only after `updateAppShortcutParameters()` is called at app activation.
- Background runs are cut off at about 30 s.
- A Personal Team build works without an App Group.

3. Time the write, build and install loop per intent.
